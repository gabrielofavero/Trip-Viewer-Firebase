# package.json scripts

Reference for every `npm run <script>` command defined in the root `package.json`. All commands run from the repository root (`Trip-Viewer-Firebase/`).

> Tip: for the full dev workflow (ports, emulators, seeding, browser sign-in), see the relevant `.github/skills/` guides (`firebase-emulators`, `browser-navigation`, `query-firestore`).

## Build

### `npm run build`

```sh
node scripts/build/build.js
```

Runs the full production build: copies `public/` → `dist/`, injects HTML partials (resolving `<!-- #include ... -->` directives), copies the Firebase config, and applies cache busting. The output lands in `dist/`.

### `npm run watch`

```sh
node scripts/build/build.js --watch
```

Same as `build`, but stays running and rebuilds whenever source files change, injecting live-reload so an open page updates automatically. Use this while developing.

### `npm run watch:fast`

```sh
node scripts/build/build.js --watch --no-livereload
```

Watch mode **without** the live-reload injection. Faster rebuilds, but you must refresh the browser manually. Handy when live reload is slow or getting in the way.

### `npm run clean`

```sh
node -e "require('fs').rmSync('dist', { recursive: true, force: true })"
```

Deletes the entire `dist/` build output folder. Safe to run anytime — `dist/` is regenerated by the next build.

## Serving & ports

### `npm run serve`

```sh
firebase serve --only hosting --port 5000
```

Serves the **already-built** `dist/` output locally via the Firebase Hosting emulator on `http://localhost:5000`. Run `build` (or `watch`) first so `dist/` exists. Note: this uses `firebase serve`, which serves the built folder directly — see `dev` for the full stack.

### `npm run kill-ports`

```sh
powershell -Command "... Stop-Process on ports 8085,9099,5000,5001,4000,8787,8788,8789,9230,9231 ..."
```

Windows utility that force-kills any process listening on the standard dev ports:

- `8085` — Firestore emulator
- `9099` — Auth emulator
- `5000` — Hosting / `serve`
- `5001` — Functions emulator
- `4000` — Emulator UI
- `8787` / `8788` / `8789` — Workers (places-api / image-proxy / etc.)
- `9230` / `9231` — Node debugger ports

Use it when ports are stuck and emulators or servers won't start.

## Development stack

### `npm run dev`

```sh
npm run kill-ports && concurrently \
  -n fn-watch,front-watch,emulators,open,worker,img-proxy,gmaps \
  "npm --prefix functions run build:watch" \
  "npm run watch" \
  "node scripts/dev/start-emulator.js" \
  "node scripts/utils/open-on-ready.js" \
  "npm --prefix workers/places-api run dev" \
  "npm --prefix workers/image-proxy run dev" \
  "npm run gmaps:server"
```

Starts the **entire local dev environment** in parallel:

1. `npm run kill-ports` — kills any processes on the dev ports (8085, 9099, 5000, 5001, 4000, 8787, 8788, 8789, 9230, 9231) before starting.
2. **fn-watch** — rebuilds Cloud Functions on change (`functions/`).
3. **front-watch** — rebuilds the frontend with live reload (`npm run watch`).
4. **emulators** — boots the Firebase emulators (Firestore 8085, Auth 9099, Functions 5001, Hosting 5000).
5. **open** — opens the app in the browser once the dev server is ready.
6. **worker** — runs the Places API worker (`workers/places-api`).
7. **img-proxy** — runs the image proxy worker (`workers/image-proxy`).
8. **gmaps** — runs the Google Maps scraper server.

This is the command you'll use for day-to-day development.

### `npm run dev:backup`

```sh
cross-env DEV_BACKUP_ON_EXIT=1 npm run dev
```

Identical to `npm run dev`, but sets `DEV_BACKUP_ON_EXIT=1` so the emulator data is snapshotted (backed up) when you exit. Useful for preserving experimental database state.

### `npm run dev:prd`

```sh
npm run kill-ports && firebase use prd && concurrently \
  -n front-watch,live-serve,open \
  "node scripts/build/build.js --watch --use-emulator false" \
  "firebase serve --only hosting --port 5000" \
  "node scripts/utils/open-on-ready.js"
```

Develops against the **production Firebase project** (`prd`) instead of the local emulators. The frontend is built with `--use-emulator false` so it talks to real Firebase, and the built output is served locally on port 5000. Use carefully — this reads/writes production data.

## Code quality

### `npm run typecheck`

```sh
tsc --noEmit
```

Runs the TypeScript compiler in type-check-only mode (no output emitted). Fails if there are type errors across the project.

### `npm run format`

```sh
npx biome format --write
```

Formats all code with [Biome](https://biomejs.dev/) in-place (writes the fixes). Use it to normalize formatting before committing.

### `npm run lint`

```sh
npx biome lint
```

Runs Biome's linter to find issues (unused imports, unsafe patterns, etc.). Reports problems without fixing them.

### `npm run check`

```sh
npx biome check
```

Runs Biome's combined check (format + lint in one pass). This is the strictest quick validation — use it to verify everything is clean.

## Repository utilities

### `npm run readme`

```sh
python scripts/utils/readme.py
```

Maintains the `README.md` task backlog: analyzes task distribution, validates task IDs and emoji consistency, detects missing/duplicate tasks, updates the summary table, and computes the project version. Run this after any README task changes (see the `backlog-management` skill).

### `npm run sync`

```sh
python scripts/utils/sync.py
```

Merges `origin/develop` into `master` (fast-forwards when possible). Non-destructive by default; if the merge hits conflicts it asks whether to force `master` to match `develop` or leave the conflicts for manual resolution (see the `git-workflow` skill). Requires a clean tracked working tree.

### `npm run backup`

```sh
node scripts/utils/backup.js
```

Creates rotating backups of the emulator data. Copies `.emulator-data/` into a timestamped folder under `.emulator-data-backups/` and keeps only the **3 most recent** backups (older ones are pruned automatically). Works whether or not the emulator is currently running.

Also prunes any stray `firebase-export-*` folders left in the repo root by ad-hoc `firebase emulators:export` runs that omitted the target directory (the CLI then auto-names them `firebase-export-<timestamp>`). `.emulator-data/` + `.emulator-data-backups/` are the single source of truth for emulator backups.

## Deployment & data

### `npm run deploy`

```sh
python scripts/build/deploy.py
```

Handles the full Firebase deployment with cache busting:

1. Prompts for the target project (`dev` / `prd` / both).
2. Labels the release version from `CHANGELOG.md` (use last / bump minor / bump patch).
3. Stamps the changelog entry and increments the build number.
4. Writes the final `version.json` to `dist/` before a **single** `firebase deploy --json` (no double deploy).
5. Persists the version state, then offers to run pending data migrations on each deployed environment.

### `npm run functions`

```sh
npm --prefix functions run build && firebase emulators:start --only functions
```

Builds the Cloud Functions and starts **only** the Functions emulator (port 5001), without the other emulators. Useful for testing functions in isolation.

### `npm run migrations`

```sh
python scripts/build/run-migrations.py
```

Runs Firestore data migrations against a live Firebase project **without** deploying functions to production. It temporarily generates a `functions/src/index.ts` that exposes only the selected migrations, runs them through the Functions emulator (which connects to the real Firestore), restores the original `index.ts`, and marks successful runs as completed per environment. See `scripts/build/migrations-config.json` / `migrations-state.json`.

Example with a project:

```sh
npm run migrations -- --project dev
```
